# Research-workbench upgrade review

## 0.3: complete an assessment and produce a decision report

The organization workflow now supports findings rather than stopping at generated requirements. Users can open a plan in **Assessment review**, record evidence/rationale, distinguish unknowns from observed gaps, assign owners/actions/dates, record acceptance and reviewer references, and export Markdown or printable standalone HTML. Local save/load and removal of the saved browser copy are explicit actions. JSON remains the portable backup.

Evidence-based observed states and recorded acceptance are structurally checked. Unknown items remain investigation tasks. Optional impact/urgency ratings order a user-supplied action queue; there is no measured readiness/compliance score. Reports preserve evidence references, unknowns, warnings and reviewer records. An acceptance reference or role name can still be false or inadequate: semantic evidence and authority review remain human responsibilities.

Validation includes 31 Python tests, the original browser-core suite and a new assessment-core suite, source-syntax checks, skill validation, and deterministic generated examples. Tests exercise unknown-state preservation, missing evidence, acceptance/reviewer gates, exclusion review, invalid dates/ratings/URLs, malformed records, report refusal and HTML escaping. An independent offline AI-agent pass found a null-field report crash; it was corrected and the rejection was confirmed by rerun. The evaluation also identified missing discovery instructions; the skill now links the complete guide and CLI workflow.

Manual desktop Brave checks exercised plan → review, unsupported finding rejection, import of the labelled synthetic example, local saving, reload/recovery, editing a finding owner while retaining evidence, printable HTML export/opening, and removal of the saved synthetic browser copy. This is a scoped functional check, not an exhaustive device/accessibility certification or academic peer review.

The included shop fixture is explicitly synthetic and adds no real institutional audit or customer outcome. Empirical coverage remains as recorded in the coverage ledger. The upgrade improves the working software; field validation with real authorized evidence remains open.

## Evaluation

An independent AI-agent forward test used only the portable skill and offline artifacts to answer a student question connecting QR growth with school technology demand. It reproduced descriptive national changes and correctly left local school need, readiness and benefit unestablished. The evaluation discovered the search/discovery gap and national-evidence relabelling defect; both were corrected and retested. A follow-up export issue was corrected and covered by a browser-core regression case.

This is a scoped behavioral test, not an independent academic peer review or a claim of real customer adoption. Python tests cover source traceability, unsupported facts, malformed inputs, dates, contradictions, chronological/unit comparisons, circular reasoning, no-overwrite behavior, exports and overlapping statistics. The browser core exercises the corresponding important evidence states and catalog consistency. UI checks cover local-file loading, search, creating a student plan, rejecting an unsupported claim and opening a worked study. Broader device and accessibility testing remains open.

## Research still required

Only selected payment evidence has expanded in this upgrade. Most domain leaves, current provincial/local source records, local budgets and actual institution needs, broader statistics, active technology reporting and engineering dossiers remain open. There is no continuous crawler or monitoring deployment. The three payment studies use one publication and are not independent corroboration of one another.

The next research contribution should complete a bounded question with owning-source evidence, reproducible extraction/analysis and an appropriate local or subject reviewer. More topic counts cannot substitute for that work.

The upgrade also attempted current official Banganga budget access and NSO household/province evidence retrieval. Direct access timed out or returned 502; those candidates remain in [the verification frontier](../sources/next-verifications.json). Search-visible values were not silently promoted to audited observations. A failed request is not proof that a source, budget or opportunity is absent.
